## Repository references and real entry paths

Searched every removed identifier across the entire tracked repository at both baseline and head, excluding the class itself and explanatory documentation. Both revisions produce the same 15 matching lines / 16 identifier occurrences. All belong to **other owners**: JourneyReturnCampEvent's local/relationship adjustTrust, DealConsequencesSystem's trust/suspicion helpers, SocialEngine's effects helper and SocialMemorySystem.adjustTrust. None calls a removed ConversationSystem method. [removal-reference-check.json](qa/removal-reference-check.json) records the owner-reviewed head results.

Also inspected qualified conversation calls, bracket/dynamic dispatch, UI handlers, event subscriptions, save restore and debug/QA callers. Conversation navigation callbacks now close over semantic definitions; they do not dispatch removed names. No runtime external consumer requires a removed ConversationSystem method. The repeatable audit rejects any new unreviewed reference to a removed name, verifies the complete baseline-to-head inventory when the baseline git object is available, and verifies replacement/coverage records in shallow CI.

Actual entry paths remain:

- Camp Talk/Approach/Join → CampInteractionSystem → startPlayerConversation → physical reservation → ConversationView → ConversationResolver.
- Pre camp invitation/confrontation event → retained conversation entry → real reservation → semantic opening. Post approach_player → physical route/arrival → approach_wait invitation → accepted conversation → semantic objective/task request.
- NPC/NPC timed exchange → CampActivity / ScrambleActivityPlan → existing agenda or semantic objective/task execution.
- Formal alliance UI/meeting → retained startAllianceConversation → AllianceConversation / AllianceSystem. Generic deals own specific obligations only.
- Save restore → existing ordered system deserializers → reservation/checkpoint resume. Rendering a cached answer never resolves that answer again.

## Save compatibility

Compatibility tests construct the actual #355 payload shapes: conversation moods, memoryLog, npcMemory; existing canonical SocialMemory; post-immunity activity reservation and cached choice outcomes; alliance state; historical accepted FINAL_TWO Deal. Missing semantic state creates empty objectives/tasks/receipts and preserves existing owned information. Historical deals remain protection obligations and never manufacture formal membership.

#355 pre-immunity saves did not serialize an active conversation reservation/transcript. Loading those saves resumes camp and clears the orphan reservation while retaining history. Reconstructing an absent transcript would invent information, so it is deliberately not attempted. Newly saved #356 pre conversations do retain their semantic checkpoint/transcript.

Legacy local fields are preserved for compatibility, not silently promoted into objective truth or distributed to other contestants. New memory belongs to the canonical owner-specific architecture.

## Validation limits

The inventory/reference validator proves completeness of method disposition and absence of unreviewed callers; a coverage filename alone is not behavioral proof. The family matrix is backed by executable action, knowledge, lifecycle, save, convergence and rendered tests. Finite templates cannot guarantee every emergent season is compelling; that remains a playtest judgment. This audit found and fixed concrete missing capabilities without restoring the deleted architecture.
